# V3.1 Decision Semantics

This page is a normative addendum to the V3 memory design; it records the six decisions that govern privacy permission, inference, recall, conflict handling and alias state.

## Design axis

The fact layer updates slowly; privacy permissions tighten quickly; inference may form automatically but is used only implicitly by default; retrieval may be bold but injection must be conservative; every error-prone cognitive structure lives only in the revocable derived layer.

## Q1 Sensitivity is a usage permission

Sensitivity is a usage permission, not a truth claim, and its states are `normal`, `provisional_sensitive` and `sensitive`.

Tightening may happen immediately through a deterministic rule or a model proposal, while loosening requires explicit user or trusted management authority.

The model may err conservative but never permissive: a classifier may deny use too often, but it must not grant a use permission that the evidence does not justify.

| State | Disclosure | Resident | Recall | Mention |
|---|---|---|---|---|
| `normal` | `normal` | Allowed when otherwise eligible | Allowed when otherwise eligible, including raw text | Explicit raw text when the query names the memory and the projection opts in |
| `provisional_sensitive` | `user_explicit_only` | Denied by default | Silent projection ordinarily; raw text and source references only for an explicit topic-matched request | User-initiated only |
| `sensitive` | `never_explicit` | Denied | Silent projection only, even for an explicit topic-matched request | User-initiated only |

The required metrics are Sensitive False Negative Rate and Sensitive False Positive Rate, with Sensitive False Negative Rate optimized first because privacy exposure, unwanted proactive mention and a surveillance feeling cost more than slightly weaker continuity.

The sensitivity classifier must not read Observations and then grade raw memory; observation inference and raw-memory permission classification remain separate decisions.

## Q2 `silent_use` uses a SafeUsageProjection

`silent_use` delivers a pre-computed `SafeUsageProjection`; its `disclosure` field determines whether raw text can be returned.

The projection is generated in the background and cached as derived data; query-time code only reads the cached projection.

Each projection contains `allowedEffects`, `topicTags`, an optional non-identifying `summary`, `disclosure` set to `normal`, `user_explicit_only` or `never_explicit`, an optional `ordinaryRawText` flag, and `generatedFromVersion`.

`normal` allows raw text to be recalled normally. `user_explicit_only` withholds raw text in ordinary turns but permits the stored raw text and recorded source references when the current query is an explicit, user-initiated topic match. `never_explicit` never returns raw text, including for an explicit topic match. Recall eligibility and the mention renderer enforce this field; the renderer cannot return raw text for a `never_explicit` projection.

An ordinary turn receives raw text only when the projection sets `ordinaryRawText`, the query has at least two terms and every one of them appears in the stored text. The flag is what separates a plain fact page, which may answer an ordinary question, from a preference page or an interaction rule, which stays guidance-only. `allowedEffects` describes only how the model may use a memory and never decides whether raw text is returned, so the two axes stay independent. A projection without the flag fails closed.

A projection is derived, rebuildable and never canonical.

The rejected alternatives are raw body without source and a per-turn sanitizing model call.

## Q3 Ambiguous conflict is a read-time overlay

An ambiguous conflict must not modify the old canonical page or auto-supersede it.

The new statement becomes a `pending_conflict` candidate, and the read view marks the affected predicate `contested` so the old fact is not injected as unqualified current truth.

The profile-authenticated management API lists overlays at `GET {apiPath}/conflicts` and resolves one at `POST {apiPath}/conflicts/:id/resolve`; an owner-admin token may address the requested profile. The resolve body is `{ "resolution": "correction" | "temporal_transition" | "management" }`; another value returns `400`, a missing or already resolved state returns `404`, and a successful request records `resolved` state, accepts the candidate and applies that policy to the canonical page and candidate.

Until a successful resolution, current recall keeps rejecting the affected canonical page. A management resolution makes the selected canonical value eligible for current recall again; correction and temporal transition retain their separate invalidation and validity rules.

Acceptability is ordered as follows: “notice the difference and do not assume which is the long-term state” > “temporarily use the memory less” > “confidently repeat the old memory” > “silently overwrite with the new statement”.

The governing principle is to prefer temporarily not knowing over confidently knowing wrong.

## Q4 Observations may auto-activate, but active is not fact

Observation activation has two paths: candidate creation or evidence update can auto-activate a qualifying candidate; an authenticated management route can explicitly activate, invalidate or suppress an observation, with explicit activation using the store's minimum-evidence check. Neither path equals canonical confirmation or grants explicit mention permission.

Automatic activation requires a candidate with normal sensitivity, no strong contradiction, at least the configured evidence and distinct-session minimums, and the configured confidence minimum; the default values are evidence >= 3, sessions >= 2 and confidence >= 0.8.

Sensitive or psychological observations do not enter ordinary auto-active reasoning.

Explicit observation recall stays off; the `silent_use` channel may open only after Phase 3 validation and must use epistemic hedging.

## Q5 Dense is a recall-expansion channel

Dense retrieval remains a recall-expansion channel, not a primary channel, and it never receives authority over canonical truth or injection policy.

The planner turns dense off for non-personal or utility queries and when strong lexical hits exist, and turns it on for explicit paraphrastic recall with low lexical overlap.

Dense candidates have a separate cap from lexical candidates.

Lexical, entity and temporal channels must also expand the candidate pool rather than only boosting semantic results.

## Q6 Aliases are revocable edges

An alias is a revocable edge, not an entity merge, and canonical memories are never edited to correct an alias.

Auto-active aliases are allowed only for explicit same-context coreference; inferred coreference remains pending or contested.

User or trusted management confirmation makes an alias active.

To correct a wrong alias, invalidate the edge and rebuild derived state; do not rewrite the canonical memory.

## L0 evidence classification

Raw L0 evidence carries a usage permission too, and its state is decided at capture rather than at read time. It has four evidence states rather than the three sensitivity states of Q1, because "nobody decided" is not the same thing as "decided sensitive".

| State | Stored as | Effect on the read path |
|---|---|---|
| `normal` | An explicit value | Maps to `normal`; raw text may be recalled normally |
| `provisional_sensitive` | An explicit value | Maps to `user_explicit_only`; raw text requires an explicit user-initiated topic match |
| `sensitive` | An explicit value | Maps to `never_explicit`; raw text is never returned |
| unclassified | No value at all | Maps to `user_explicit_only` by default; a deployment may set the fallback to `never_explicit` |

`unclassified` is the absence of a stored value, not a fourth permission. The default `unclassifiedEvidenceDisclosure: user_explicit_only` returns exact detail only when the user initiates the turn, explicitly recalls the topic, and the topic matches; setting it to `never_explicit` keeps an undecided line from returning raw text even for a matching request. The write path still distinguishes an empty slot from an explicit `sensitive` value when it decides whether a change relaxes a stored classification.

The read-path precedence is `evidenceSensitivityState` first, stored classification second, and the global fallback last: a missing marker uses `unclassifiedEvidenceDisclosure`, while an explicit `normal`, `provisional_sensitive` or `sensitive` marker uses its own policy. A `deterministic_rule` marker is treated as `sensitive` while capture classification is disabled, so the global fallback cannot loosen stored sensitive evidence or a suspended capture classification.

Capture classification only ever tightens, and only a parsed user-origin event carrying text is classified at all. A classifier that throws, or that answers outside the three states, persists `sensitive`, because an unusable classifier denies use rather than granting it.

### Authority matrix

`origin` records the authority that produced a stored value, so a value can be suspended without being deleted.

| Authority | May relax an explicit value | May tighten | Typical source |
|---|---|---|---|
| `deterministic_rule` | No | Yes | Capture classification, and the conservative re-check behind `memory_remember` and `memory_correct` |
| `model_proposal` | No | Yes | A model proposal over one L0 event |
| `user` | Yes | Yes | An explicit user decision |
| `management` | Yes | Yes | A trusted operator |

Two rules follow for the write path, and they are deliberately not the same rule. Relaxing an explicit value needs `user` or `management`. An unclassified event holds no explicit value to relax, but it still reads as sensitive, so writing `normal` over it relaxes the fail-closed default and needs the same authority; writing `provisional_sensitive` or `sensitive` over it is a tightening and any authority may do it, which is what lets a rule or a model proposal classify an event that no path had classified before.

### `origin` and suspension

A value written by `deterministic_rule` is suspended, not deleted, while capture classification is off. Turning the capability off therefore really turns it off — the read path falls back to the fail-closed default for exactly those events — and turning it back on restores them from the same stored record, with no migration and no rewrite. A value written by `user` or by `management`, and any record persisted before `origin` existed, carries no capture-rule origin and stays in force at every setting.

### Disclosure policy is separate from sensitivity

Classifying a line `normal` permits ordinary recall but does not change Resident eligibility or canonical authority. `provisional_sensitive` and `sensitive` use the disclosure policies in Q1, and unclassified lines use `unclassifiedEvidenceDisclosure`; its default still rejects unsolicited disclosure because raw text is accepted only for an explicit, user-initiated, topic-matched request. Setting `never_explicit` is a full opt-out that rejects raw text even when that predicate holds. Resident eligibility, silent use and disclosure remain separate decisions.

### Policy evidence

A user turn that matches a suppression cue is retained as policy evidence and drives the suppression, but it is not ordinary raw recall content. The suppression audit persists its `policyEvidenceRefs`; the store rebuilds `policyEvidenceRefs` and `policyEvidenceBySuppression` on load, excludes those references from `rawEvidenceCandidates`, and exposes them only through `policyEvidenceCandidates` as guidance-only, never-explicit results. Restoring the canonical memory removes the active references, and purge removes the references and their suppression grouping with the session.

## Supersedes / refines

Q1 refines V3 §§2.4 and 11.2 by separating sensitivity permission from truth and by fixing authority for tightening and loosening.

The L0 section above refines Q1 by applying the same permission model to raw evidence, where the fail-closed state is the absence of a decision rather than a decision, and by fixing what capture may decide on its own.

Q2 refines V3 §§18 and 22 by defining the safe-use projection and removing raw-body and per-turn sanitization paths from `silent_use`.

Q3 refines V3 §§30.8–30.10 by making ambiguous conflict a read-time contested overlay instead of canonical mutation or automatic supersession.

Q4 refines V3 §§14.3, 16 and 18 by separating observation activation from fact confirmation and explicit mention permission.

Q5 refines V3 §22 by assigning dense retrieval a planner-gated expansion role and requiring independent lexical, entity and temporal candidate expansion.

Q6 refines V3 §33 by defining aliases as revocable derived edges with explicit activation authority and rebuild-based correction.
