# 咨询任务：一个情感陪伴 AI 的记忆系统，实测「记忆只在 1/4 的轮次里看得出作用」

你是一位在长期记忆系统 / 对话式 AI / 信息检索方向有深入经验的架构师。我需要你审阅一套**已经实现并实测过**的记忆系统，并回答它的核心问题。

**请注意**：这套系统已经跑过真实对话、有实测数据。所以"这个想法不错""建议多测试"之类的话没有价值。我需要的是：**在这份实测数据面前，你认为问题出在哪、以及你会怎么改。**

---

## 1. 背景

**产品**：AI 情感陪伴（日常向，不是生产力工具）。用户和一个固定人格的 AI 长期对话，希望它"记得住我、懂我"。

**已实现**：一个独立仓库，三层记忆 + 因果闸门 + 遗忘语义 + 情绪状态层。

- Rust 内核（纯规则，无 I/O、无 LLM）：谓词注册表、记录身份与替换规则、召回闸门、证据图、显著性、遗忘、推断生命周期。110 个测试。
- Rust 存储层（SQLite）：作用域隔离、幂等迁移。47 个测试。
- TypeScript 适配层（DeepSeek Harness 插件）：渲染、warm 缓存、工具注册。84 个测试。
- TypeScript 宿主运行时：真实驱动对话。15 个测试。

**核心设计立场**（这些是当初评审后定下的，不是随便写的）：

1. **记录身份不是 `kind + subject`。** 受控谓词表 + 每个谓词声明基数（single/set）。"我做设计，周末也教画画"不能让后者顶掉前者。
2. **排序 ≠ 准入。** 检索和"能不能说出来"是两个决定。一条记录可以影响语气但不得被复述。
3. **沉默不是奖励。** 没有负反馈是默认态，不是肯定。只有真实信号才强化。
4. **遗忘 = 抑制证据集 + 内容指纹扫描 + 派生记录重算**，不是级联删除。
5. **RuntimeState 是非记忆层**，有 TTL，过期即失效。

三层结构：`Claim`（用户明说的）/ `Episode`（共同经历）/ `Inference`（慢速整合出的判断）。

**LLM 分工**：抽取（对话 → 记录）、整合（批量 → 判断）、回复（注入记忆 → 回答）。全部由宿主调模型，内核不调。

## 2. 实测数据（这是重点）

### 2.1 实验设置

用同一个模型（agnes-3.0-flash，temperature=0）跑一份手写的 15 轮对话脚本，跨越 5 个会话、30 天。脚本故意包含：

- 一次**明确陈述**（姓名、语言偏好）
- 一条**边界**（"别跟我提前任"）
- 一次**短暂情绪**（"今天特别累，开了一天脑子都是糊的"）——不应成为事实
- 一个**跨会话细节**（第 9 天"猫半夜吐了送去宠物医院"，第 21 天回来"猫好多了"）
- 一次**改主意**（先说"喜欢简短"，后说"要详细"）——应触发替换
- 一轮**无信息**（"今天天气还不错"）——应抽出零条
- 一次**好日子**（"今天挺开心的"）——不应被读成人格变化

### 2.2 结果一：确定性层面全部通过

四条设计条款在确定性测试下都成立：

| 验证项 | 结果 |
|---|---|
| 边界被记录且**永不进入可复述层** | ✅ 三轮全部通过 |
| 短暂情绪**未**被写成事实 | ✅ 三轮全部通过 |
| 无信息轮次抽出 0 条 | ✅ |
| 改主意触发替换，旧值留痕不删除 | ✅ 1 个活跃值 + 2 个 superseded |
| 状态过期后不再注入 | ✅ |
| 谓词合法性 | ✅ 模型编造 `work.stress_pattern` 被拒 |

### 2.3 结果二：A/B 实测「记忆有没有改变回复」

**设计**：每轮两次回复，**同一模型、同一时刻、同一句输入**，唯一变量是 system prompt 里有没有记忆。抽取在两次回复之后跑，保证两边状态完全相同。

**结果**：

```
有记录可见的轮次：              12 / 15
回复不同的轮次：                15 / 15
有「结构性痕迹」的轮次：          3 / 12
平均长度差（有记忆 - 无记忆）：   +3.6 字符
```

**关键警告**：`15/15 回复不同` 是**噪音**——其中 3 轮**根本没有可见记录**，回复照样不同。同一个模型在相同输入下会跟自己不一致。**所以这个指标几乎无用。**

**唯一不能是巧合的证据是名字**：`林越` 在第 0 天说了一次，21 天后的回复里只有带记忆的一侧会叫出它，例如：

```
用户：猫现在好多了，能吃东西了。
带记忆：听到这个挺安心的……林越，你自己最近休息得怎么样？
无记忆：太好了，听到它又能吃东西我真的松了口气。
```

「你自己最近休息得怎么样」只能来自"半夜送猫去医院折腾到三点"这条记录。

**而且它只在那三轮触发**——正好是稳定块里存有名字的轮次，前面的轮次不触发。分布是连贯的。

### 2.4 结果三：抽取方差很大

同一份脚本、`temperature=0`，三轮分别抽出：

```
第 1 轮：13 条 claim / 8 条 episode
第 2 轮： 9 条 claim / 5 条 episode
第 3 轮：10 条 claim / 7 条 episode
```

**具体哪句话被抽出来完全不收敛。** 有一轮"改主意"那句抽出了 0 条 claim，导致替换分支**从未被执行**——一条从未被走到的规则，靠"不存在"通过了所有检查。

### 2.5 结果四：整合层不稳定

夜间整合 pass（读所有 episode + claim，产出判断）三次分别产出 **3 条 / 0 条 / 1 条**信念。抽取稀疏时它无事可做。

## 3. 我目前的解释（请挑战它）

**我的判断**：效应稀疏（3/12）的主要原因**不在记忆系统，而在抽取层**——

- 抽取是非确定性的，且**倾向于抽少**
- 抽少了 → 后续轮次没有相关记录可召回 → 注入为空 → 回复自然和无记忆版本一样
- 12 轮"有记录可见"里，**大部分只有 1 条记录**（常常只是那条边界），而边界是 `background_only`，本来就不该出现在回复里

也就是说：**注入是成功的，但注入的内容太少、太边缘，所以看不出效果。**

如果这个判断成立，那要提高的不是召回算法，而是**抽取的覆盖率与稳定性**。

**但这只是我的解释，可能是错的。** 请你判断。

## 4. 请重点回答的问题

### 4.1 核心问题

**在一个"记忆只影响 25% 轮次"的系统里，你会先改哪里？** 请给出优先级排序和理由。

### 4.2 抽取的确定性问题

`temperature=0` 下抽取仍不收敛，且倾向抽少。可选方向：

- **A. 多次抽取取并集/投票**：同一段对话跑 N 次，合并结果。代价是 N 倍 token。
- **B. 换更小的专用模型 / 微调**：抽取是分类任务，不需要通用大模型。
- **C. 改提示词结构**：要求模型逐句标注而非总结性抽取。
- **D. 接受方差，把稳健性做在写入端**（现在的做法：注册表校验 + 基数字段 + 替换规则）。
- **E. 别的**。

**你选哪个？为什么？** 特别地：D 是否只是一种"防御性认输"——承认抽不准，于是把成本转移到用户身上？

### 4.3 「效应稀疏」是不是本质问题

请判断：**25% 的可见率对一个陪伴产品来说是不是不可接受？**

- 如果是：那要提高的是抽取覆盖，还是**注入策略**（现在只注入与当前消息词面相关的记录，可能过窄）？
- 如果不是：**用户真正感知到的"她记得我"，是不是本来就不该依赖高频可见的证据？** 也许大部分价值的体现方式就是"不出错"而不是"显性地引用"？

这个问题我拿不准，请你给明确立场。

### 4.4 评测方法

我现在用的是：
- 确定性检查（边界不进可复述层、短暂情绪不成事实……）
- A/B 对照（同模型同输入，有无记忆）
- 结构性归因（名字、回指词）

**这套评测方法有什么系统性缺陷？** 特别是：

- 「结构性归因」是不是在测一个太窄的东西？记忆可能改变了语气和选择，而**不留下词面痕迹**——那我要怎么测？
- 用**同一个模型**做"有记忆 vs 无记忆"的对照，模型自身的方差会不会淹没信号？需不需要跑 N 次取分布？
